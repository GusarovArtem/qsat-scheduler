# Stage 1.1
Концепт перед кодом: что такое dataclass?
В backend-разработке часто нужны простые data-контейнеры (DTO, Value Object).
В Java пишешь конструктор, equals, hashCode, toString вручную.
Python генерирует всё это автоматически через декоратор @dataclass.
frozen=True делает объект иммутабельным — аналог record в Java 16+ или data class в Kotlin.
Поля нельзя менять после создания. Это важно для доменных объектов: спутник не должен неожиданно «переехать».

Реальный TLE МКС с сайта CelesTrak выглядит примерно так:

ISS (ZARYA)
1 25544U 98067A   24001.50000000  .00001 00000-0 00001-4 0  9999
2 25544  51.6400   0.0000 0001000   0.0000   0.0000 15.50000000    0

Исторически: формат TLE разработали в 1960-х под перфокарты и телетайп — максимум 69 символов в строке. 
Параметры орбиты не помещались в одну строку, поэтому разбили на две.

Строка 1 — «когда и что»: номер объекта, эпоха (момент записи), коэффициенты торможения атмосферой.
Строка 2 — «как летит»: наклонение орбиты, высота, скорость, положение в момент эпохи.

Формат не менялся 60 лет — слишком много систем на него завязано.
Это типичный пример технического долга планетарного масштаба.

В коде мы просто храним обе строки как есть и передаём их в библиотеку skyfield в Stage 1.3 — она знает как их распарсить.

@dataclass(frozen=True) — декоратор (аналог аннотации в Java). Генерирует __init__, __repr__, __eq__. frozen=True запрещает изменение полей после создания.
__post_init__ — специальный метод, который dataclass вызывает после своего __init__. Единственное правильное место для валидации в frozen dataclass.
f"..." — f-string, аналог string interpolation: f"got {self.norad_id}" подставляет значение переменной.
